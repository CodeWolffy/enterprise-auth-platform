# 模块边界规范

本规范用于约束模块化单体的代码归属和依赖方向，避免新代码重新回到大平层。

## 一、顶层边界

| 区域 | 职责 | 禁止内容 |
|---|---|---|
| `common` | 跨模块共享内核 | 具体业务流程、模块私有 DTO、模块私有枚举 |
| `modules` | 业务模块 | 其他模块的 domain / infrastructure 直接依赖 |
| `infrastructure` | 技术适配 | 业务规则、业务 Entity / Mapper、业务编排 |
| `interfaces` / `application` / `domain` / `infrastructure` | 模块标准分层 | 新增大平层包、跨层直连、历史包扩张 |

## 二、模块内分层

```text
interfaces -> application -> domain
                      └── infrastructure
application -> common
```

| 层级 | 可以做 | 不可以做 |
|---|---|---|
| `interfaces` | 接收请求、参数校验、响应转换 | 写业务流程、直接访问 Mapper |
| `application` | 编排用例、事务边界、跨模块 facade 调用 | 堆积无关子域，形成新的大 Service |
| `domain` | 业务规则、状态判断、策略 | 依赖 Web、数据库、Redis、其他模块 |
| `infrastructure` | Entity、Mapper、模块私有配置、外部适配 | 被其他模块直接引用 |

## 三、允许依赖

| 来源 | 允许依赖 |
|---|---|
| `modules/{a}/interfaces` | 本模块 application、common/web |
| `modules/{a}/application` | 本模块 domain、本模块 infrastructure、common、其他模块 application facade |
| `modules/{a}/domain` | common、本模块 domain 内对象 |
| `modules/{a}/infrastructure` | common、本模块 domain、技术依赖 |
| `common` | JDK、稳定基础库、少量 Spring 基础能力 |
| `infrastructure` | common、技术框架、全局配置 |

## 四、禁止依赖

| 禁止项 | 原因 |
|---|---|
| A 模块引用 B 模块 `domain` | 破坏业务边界，后续无法拆分 |
| A 模块引用 B 模块 `infrastructure` | 绕过契约，直接耦合数据库或技术实现 |
| Controller 直接注入 Mapper | 入口层膨胀，绕过应用层用例 |
| `common` 引用业务模块 | 共享内核反向依赖，形成循环 |
| 业务 Entity / Mapper 放入全局 `infrastructure` | 技术设施变成业务杂物间 |
| 业务 Properties 放入全局 config | 配置归属不清，后续拆分困难 |

## 五、常见归属判断

| 内容 | 归属 |
|---|---|
| `TenantContext`、`RequestContext` | `common/context` |
| `ApiResponse`、全局异常处理、限流注解 | `common/web` 或 `common/exception` |
| 权限码常量、数据范围公共契约 | `common/authz`，权限码统一登记在 `PermissionCodes` |
| 审计事件契约 | `common/audit` |
| Redis 配置、Sa-Token Storage 配置 | `infrastructure/redis` |
| MyBatis-Plus 全局配置 | `infrastructure/persistence` |
| Sa-Token 技术胶水 | `infrastructure/security` |
| 登录、注册、验证码、会话策略 | `modules/auth` |
| 租户生命周期、套餐能力、变更日志 | `modules/tenant` |
| 字典、参数、公告、分类规则 | `modules/system` |

## 六、跨模块协作方式

| 场景 | 推荐方式 | 禁止方式 |
|---|---|---|
| 登录后生成菜单 | auth application 调 resource application facade | auth 直接查 resource Mapper |
| 删除部门前检查用户引用 | dept application 调 user query facade | dept 直接查 user Mapper |
| 租户切换刷新权限快照 | auth application 编排权限快照 | Controller 拼装租户和权限数据 |
| 业务审计 | 发布 common/audit 契约事件 | 各模块散落调用审计落库细节 |

## 七、实施规则

- 新入口接管后，不保留旧转发或旧职责。
- 每次调整只移动一个清晰职责，不做批量无边界搬家。
- 包移动后必须验证 Spring 扫描、Mapper 扫描、配置绑定、主链路测试。

## 八、评审清单

| 检查项 | 结果 |
|---|---|
| 新代码是否进入目标模块，而不是继续扩旧 service | 需要确认 |
| Controller 是否只依赖 application | 需要确认 |
| 是否新增跨模块 domain / infrastructure 依赖 | 需要确认 |
| DTO / Properties / Mapper 是否归属正确 | 需要确认 |
| 权限码、菜单、路由、初始化数据是否一致，后端是否引用 `PermissionCodes` 而非散落字符串 | 需要确认 |
| Flyway 脚本是否是新增版本而非修改旧版本 | 需要确认 |
