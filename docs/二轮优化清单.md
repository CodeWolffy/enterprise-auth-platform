## 三、仍需治理的二轮后续项

| 优先级 | 事项 | 当前问题 | 验收标准 |
|---|---|---|---|
| P0 | 跨模块 facade 收敛 | 已完成：Auth/User 主链路与 Tenant 删除前关联检查已改为应用层 facade；P1 历史依赖暂不纳入本轮门禁 | 已验收：已治理链路不直接注入对方 Mapper / Entity |
| P0 | Auth 与 User 边界收敛 | 已完成：登录、当前用户、权限适配统一通过 `UserAuthenticationFacade`，User 模块对外认证模型改为 `AuthenticationUser` | 已验收：`auth` / `security` 不依赖 `user.infrastructure` / `user.domain` |
| P0 | Tenant 与 Resource / Role / Dept / User 边界收敛 | 已完成：租户删除前关联检查通过 User / Role / Dept facade 完成；租户初始化和资源能力链路仍归入 P1 继续治理 | 已验收：`tenant` 不依赖 user / role / dept / resource 的 `domain / infrastructure` |
| P1 | Resource 与 Role / Tenant 边界收敛 | 资源授权和租户覆盖仍直接访问角色、租户表 | 资源模块只维护资源树和权限码，授权关系通过角色/租户 facade 协作 |

| P1 | `config` 过渡区拆分 | 业务配置与技术配置仍部分混放 | 技术配置归 `infrastructure/config`，业务策略配置归属模块 |
| P1 | `security` 过渡区拆分 | 当前用户、安全缓存、Sa-Token 胶水仍在同一过渡区 | 当前用户语义归 `auth`，Sa-Token 技术适配归 `infrastructure/security` |
| P2 | 测试包路径同步 | 部分测试包名仍保留历史语义 | 测试包路径与目标模块路径一致，便于按模块定位 |
