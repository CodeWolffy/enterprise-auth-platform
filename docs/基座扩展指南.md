# 基座扩展指南

本指南用于在当前基座上新增业务模块，目标是让后续功能只沿固定入口扩展，不回流到大平层。

## 一、新增后端模块

推荐结构：

```text
src/main/java/com/enterprise/auth/platform/modules/{module}/
├── interfaces/       # Controller、入口请求/响应
├── application/      # 用例编排、跨模块 facade
├── domain/           # 规则、策略、状态判断
└── infrastructure/   # 本模块 Entity、Mapper、模块私有配置
```

落地顺序：

| 顺序 | 动作 | 要求 |
|---|---|---|
| 1 | 建模块目录 | 至少建立 `interfaces`、`application`，复杂模块再补 `domain`、`infrastructure` |
| 2 | 定入口契约 | URL、Method、请求字段、响应字段先固定，避免后续前端反复改 |
| 3 | 建应用层入口 | Controller 只转发到 application，不直接拼业务流程 |
| 4 | 放业务规则 | 可复用判断进入 domain，不放 Controller 或 common |
| 5 | 放数据适配 | Entity、Mapper、模块私有 Properties 跟随模块进入 infrastructure |
| 6 | 补测试 | 至少覆盖主链路、权限边界、租户边界、异常语义 |
| 7 | 跑边界校验 | 模块不能引用其他模块的 `domain` / `infrastructure` |

## 二、新增前端模块

推荐结构：

```text
frontend/src/modules/{module}/
├── manifest.ts       # 路由、菜单、权限、图标、标题声明
├── api.ts            # 模块 API 聚合入口
├── views/            # 页面
├── components/       # 模块内组件
└── composables/      # 模块内组合能力
```

接入顺序：

| 顺序 | 动作 | 要求 |
|---|---|---|
| 1 | 新增页面 | 页面不直接写全局菜单和全局权限映射 |
| 2 | 新增 manifest | 声明 `routeKey`、`path`、`component`、`title`、`icon`、`permission` |
| 3 | 注册到 `ModuleRegistry` | 路由、菜单、访问映射统一从 manifest 派生 |
| 4 | 补 API 模块 | 业务 API 放入 `frontend/src/api/modules/` 或模块私有 API 入口 |
| 5 | 补 E2E | 至少覆盖可访问、无权限不可见、关键写操作反馈 |

## 三、新增权限码

权限码必须同时进入三条链路：

| 链路 | 位置 | 要求 |
|---|---|---|
| 后端校验 | Controller 或应用层入口 | 使用统一权限码，不写临时字符串 |
| 资源数据 | Flyway 增量脚本 | 菜单、按钮、`routeKey`、`grantKey` 保持一致 |
| 前端声明 | manifest / 权限判断 | 与后端 `grantKey` 完全一致 |

命名建议：

```text
{module}:read
{module}:write
{module}:delete
{module}:export
{module}:approve
```

## 四、新增菜单与路由

新增页面时优先以 `routeKey` 作为稳定标识：

| 字段 | 说明 |
|---|---|
| `routeKey` | 后端权限快照、前端路由访问、菜单恢复共用的稳定键 |
| `path` | 浏览器地址，可后续调整，但需要保留兼容跳转 |
| `component` | 前端页面组件路径或注册名 |
| `grantKey` | 权限判断使用的授权键 |

要求：

- 不在 `AppNav.vue` 单独新增图标和标题映射。
- 不在 `route-access.ts` 另写一份 routeKey/path 映射。
- 后端资源初始化、前端 manifest、E2E 用例使用同一组 `routeKey`。

## 五、新增数据表

所有结构变更走 Flyway 增量脚本：

```text
src/main/resources/db/migration/V{yyyyMMddHHmm}__{module}_{description}.sql
```

要求：

| 场景 | 要求 |
|---|---|
| 新表 | 明确是否租户表；租户表必须包含 `tenant_id` |
| 新索引 | 基于实际查询路径添加，避免无依据堆索引 |
| 种子数据 | 与权限、菜单、字典等契约一起提交 |
| 大表 DDL | 脚本头部写明影响、耗时预估、回滚方式 |
| 已发布脚本 | 禁止修改，修正走新版本 |

## 六、提交前检查

```bash
mvn "-Dmaven.repo.local=.m2repo" test
cd frontend && npm run lint && npm run build
cd frontend && npm run test:e2e
```

如果只改后端或只改前端，可按影响范围缩小验证，但不能跳过对应主链路。
