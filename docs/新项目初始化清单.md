# 新项目初始化清单

本清单用于把当前基座复用到一个新企业后台项目时，逐项替换项目身份、运行环境和默认租户配置。

## 一、项目身份

| 项 | 示例 | 必做 |
|---|---|---|
| 项目名 | `enterprise-auth-platform` → `{new-project}` | 是 |
| Maven `artifactId` | `{new-project}` | 是 |
| 应用名 | `spring.application.name` | 是 |
| 包名 | `com.enterprise.auth.platform` | 视情况 |
| 前端标题 | 浏览器标题、登录页标题、导航标题 | 是 |
| README 名称 | 项目说明、启动命令、部署说明 | 是 |

## 二、数据库

| 项 | 要求 |
|---|---|
| 数据库名 | 新项目独立库，不复用旧库 |
| Flyway V1 | 已发布基线不直接改；新项目需要裁剪时生成新的基线分支或重新初始化 |
| 种子数据 | 租户、管理员、角色、资源、字典按新项目重置 |
| 权限资源 | `routeKey`、`grantKey`、菜单路径与前端 manifest 对齐 |
| 测试库 | 独立于开发库，允许重建 |

## 三、Redis 与缓存

| 项 | 要求 |
|---|---|
| Redis database | 按环境隔离 |
| key 前缀 | 替换为新项目唯一前缀 |
| Session TTL | 按安全策略确认 |
| 验证码 TTL | 保持短 TTL，按登录风险调整 |
| 权限快照缓存 | 权限、角色、菜单变更后必须可失效 |

## 四、租户默认值

| 项 | 默认建议 | 必做 |
|---|---|---|
| 平台租户 | `platform` | 是 |
| 初始业务租户 | 按项目命名，如 `tenant-a` | 是 |
| 平台超级管理员角色 | `PLATFORM_SUPER_ADMIN` | 是 |
| 默认套餐 | `basic` 或项目业务套餐 | 是 |
| 默认能力 | auth、user、role、resource、dept、tenant、system、audit | 按项目裁剪 |

## 五、认证与安全

| 项 | 要求 |
|---|---|
| Token Header | 保留 `Authorization: Bearer <token>`，除非明确改造前后端 |
| 租户 Header | 保留 `X-Tenant-Id` |
| CORS | 只配置真实前端域名 |
| 生产密码 | 不使用默认管理员密码 |
| 敏感配置 | 走环境变量或部署平台密钥 |
| 审计 | 登录、登出、租户切换、高价值写操作保留审计 |

## 六、前端主题与模块

| 项 | 要求 |
|---|---|
| Logo / 标题 | 替换为新项目品牌 |
| 主题色 | 在全局样式中统一调整 |
| 模块 manifest | 删除不用的模块，新增项目模块 |
| E2E mock 数据 | 与新项目菜单、权限、租户保持一致 |
| 视觉快照 | 新项目首次确认后再建立基线 |

## 七、环境配置

| 环境 | 要求 |
|---|---|
| dev | 本地 DB/Redis，允许调试配置 |
| test | 独立测试库，Flyway 自动迁移 |
| staging | 接近生产配置，验证部署和迁移 |
| prod | 禁止默认口令，开启健康检查和审计保留策略 |

## 八、初始化执行顺序

| 顺序 | 动作 | 验收 |
|---|---|---|
| 1 | 替换项目身份和应用名 | 启动日志、包名、README 不再混用旧项目名 |
| 2 | 准备新数据库和 Redis | Flyway 可从空库完成初始化 |
| 3 | 重置租户、角色、资源、管理员种子数据 | 登录后菜单和权限符合新项目 |
| 4 | 更新前端标题、主题和 manifest | 路由、菜单、权限守卫正常 |
| 5 | 更新部署环境变量 | staging 可启动并通过健康检查 |
| 6 | 跑全量基线验证 | 后端测试、前端 build、E2E 全通过 |

## 九、验收命令

```bash
mvn "-Dmaven.repo.local=.m2repo" test
cd frontend && npm run lint && npm run test:unit && npm run build
cd frontend && npm run test:e2e
```

## 十、禁止项

- 不在已发布 Flyway 脚本上直接修改历史结构。
- 不提交本地 `.env`、数据库密码、Redis 密码。
- 不让新业务继续堆进旧 `service` 大平层。
- 不让前端路由、菜单、权限出现多份独立硬编码。
- 不用生产库验证初始化流程。
