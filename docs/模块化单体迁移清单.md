## 第一轮保留的旧包

| 旧包 | 当前处理 | 删除时点 |
|---|---|---|
| `controller` | 暂保留 | 对应模块 `interfaces` 接管并通过回归后删除 |
| `service` | 暂保留 | 对应模块 `application/domain` 拆分并通过回归后删除 |
| `dao/entity` | 暂保留 | 对应业务模块拆分时随 Mapper 一起迁移 |
| `dao/mapper` | 暂保留 | 对应业务模块拆分时迁移到模块 `infrastructure` |
| `dao/repository` | 暂保留 | Auth / User 拆分完成后按归属迁移 |
| `dto` | 暂保留 | Controller 请求响应随接口层迁移；通用对象再进入 `common` |
| `config` | 暂保留 | 阶段 1B 按纯技术配置、模块私有配置拆分 |
| `security` | 暂保留 | 阶段 1B 按上下文、授权契约、auth 私有能力、Sa-Token 胶水拆分 |
| `common/convention` | 暂保留 | 阶段 1B 扁平化到 `common/web`、`common/exception` 等 |

## 扫描策略

| 项 | 当前策略 | 说明 |
|---|---|---|
| Spring 组件扫描 | 保持应用根包 `com.enterprise.auth.platform` | 新边界天然在扫描范围内 |
| 配置绑定扫描 | 保持 `@ConfigurationPropertiesScan` | 后续 Properties 迁移到新包后仍可识别 |
| Mapper 扫描 | 扫描根包并限定 `@Mapper` | 兼容后续模块内 Mapper，同时避免误扫应用接口 |
